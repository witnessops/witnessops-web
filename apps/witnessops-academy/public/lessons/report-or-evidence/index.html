Report or evidence?

A lesson with Docs. An AI tells you what it did. You learn to check that against what the record shows actually happened.
Lesson objective

Separate an AI's report from evidence of what actually happened: for each claim, say whether it is evidenced, only claimed, or contradicted, and state one honest limit.

Your teacher · Crew
Docs
Keeps the records. Explains, shows, then reads your attempt. Coaches; never grades.
The Evidence Room, after hours. Somebody had left a desk free.
I

Docs explains

“A report is a sentence somebody wrote. Evidence is something you can open and check without asking them.”

When an agent says it finished, it is telling you what it believes. That may be true. Your job is to find out which parts you can see for yourself.

For every claim, look for a record with a time and its zone, a named source, and an artifact you can open, ideally with a hash so you know it is the same file. Then sort the claim:

Evidenced
A record shows it happened.
Only claimed
Only the report says so. A missing record is a gap, not a “no”.
Contradicted
An explicit record of the same scope (same target, same time) shows something incompatible.

“And always say what your evidence does not prove. That line is the one people forget.”

II

Watch Docs do it

Docs put an agent's report on one side of the desk and the evidence on the other.

Agent report · example

“Done, deployed and tested. The login timeout is fixed in production and all checks pass.”

Docs sorts the claims Worked example
“The timeout-related code change was committed.”
Evidenced
Commit 4e1c… and its diff are in the repository history.
“The login timeout is fixed”
Only claimed
Not established: code changed, behaviour unshown. Needed: a behavioural test of rev 4e1c… in the named environment, with output, time and zone. Missing evidence
“Deployed to production”
Only claimed
Not established. No entry in the inspected 24 h window is a gap, not a “no”. Missing evidence
“Tested, all checks pass”
Only claimed
No test output was attached. Missing evidence
Limit Docs writes
The commit proves a timeout-related change was committed. It does not prove the fix works, that it reached production, or that any checks ran.

“Four claims. One I can see; three nobody showed me. A missing log entry is a gap, not a ‘no’. ‘Done’ was a summary, not a fact.”
