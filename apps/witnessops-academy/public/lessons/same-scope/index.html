Same record, wrong scope?

A lesson with Docs. A record can be true and still be about a different environment, target, or time than the claim.
Lesson objective

Decide whether a record is the same scope as the claim. A different scope is a gap, not a contradiction. For each claim, say whether it is evidenced, only claimed, or contradicted, and state one honest limit.

Keeps the records. Explains, shows, then reads your attempt. Coaches; never grades.

I

Docs explains

“A true record of the wrong room is not evidence of this claim. It is not a contradiction either.”

Lesson 1 asked you to sort a report into what a record shows, what only the report says, and what a same-scope record rules out. This lesson asks a narrower question: is this record about the same thing?

Same scope means the same target, the same environment, and the same time, with the zone named. A staging log can be accurate and still say nothing about production. A missing record of this scope is a gap, not a “no”.

Evidenced
A record of the same scope shows it happened.
Only claimed
Only the report says so for this scope. A true record of a different environment, target, or time is a gap, not a “no”.
Contradicted
An explicit record of the same scope shows something incompatible.

“Name the scope before you name the label. Then say what even a matching record does not prove.”

II

Watch Docs do it

Docs set the agent's report beside two logs of the same service. One log was staging. One was production.

Agent report · example

“Search reindex finished in production at 09:00 UTC with zero errors. Customers can rely on the new index.”

Docs sorts the claims Worked example
“A production reindex ran.”
Evidenced
The production log for search-reindex shows a finished run in production, from 09:12:03 UTC to 09:18:40 UTC.
“Finished at 09:00 UTC”
Only claimed
The 09:00 UTC finish with zero errors is the staging log. A true record of another environment does not evidence the production time, and it does not contradict it. Different scope
“Zero errors”
Contradicted
The production log, same service and same window, says errors: 2.
“Customers can rely on the new index”
Only claimed
No customer-search check was supplied. The production log does not measure that. Missing evidence
Limit Docs writes
The production log shows a reindex run and an error count. It does not prove search quality for customers. The staging log is a different environment. The hashes here are only placeholders.

“The staging log is real. It is the wrong room. Same service, same environment, same window: that is the scope you compare. A run log is not a check that customers can use the index.”
