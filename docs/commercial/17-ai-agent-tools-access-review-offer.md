## Buyer and result

For an engineering or security owner whose coding agents and tool connections
can reach meaningful repositories, data, cloud, CI/CD, support or operational
systems. The buyer receives a dated, source-bounded picture of agent tooling
observed on agreed devices, one selected tool connection, and a deeper review
of one consequential action's authority, effective permissions and evidence.
The primary Polish name is **Przegląd narzędzi i dostępu agenta AI**.

## Normal reference scope

The normal starting-price scope covers **one agreed device and OS**, with:

1. One **dated system-level application/package inventory or managed-endpoint
   inventory export**. State its coverage. A PATH lookup alone is insufficient.
2. One named agent setup: relevant user/project configuration and available
   application or CLI identity/state.
3. One selected MCP/tool connection: declaration or equivalent client
   configuration and a redacted capability description where needed.
4. One proposed or observed consequential action: customer authority/approval
   rule and downstream effective-permission evidence. For an observed action,
   inspect relevant execution/audit evidence if available. Do not infer that
   an action occurred from configuration alone.

The fixed quote names actual sources, owner, access method, device, OS,
connection, action, downstream boundary and exclusions. One source may answer
multiple questions when its provenance and coverage suffice. Broader cloud
inventories, extra devices/OSs, IDEs, agent setups, connections, inventories,
or reconciliation of conflicting sources expand the quote. Action-specific
downstream records are part of the chosen action, while an estate-wide
inventory of that downstream service is not.

If a minimum source cannot be supplied during scoping, use an approved
alternative, a separately quoted limited scope, or the private pilot. Do not
sell a limited-source review as the normal full review.

## Coverage and deliverables

For each agreed source record device, source, inspection method, observation
time and one of **observed**, **not found within source**,
**unavailable/failed**, or **not inspected**. These are different outcomes;
none implies complete discovery. An unavailable source never becomes an
absence finding. State any redaction that limits interpretation.

Deliver a scope and coverage matrix; bounded observed agent/tool and selected
connection map; one action reconstruction from authorization through the
executable path to observed evidence and unresolved questions; prioritized
findings with source, practical fix and unknowns; and a buyer readout. The
report has a fixed revision. One consolidated factual-correction round is
included if requested within five working days of handover. New devices,
sources, actions or remediation require new scope.

## Authority and evidence handling

The customer-specific agreement/SOW identifies both legal parties and
decision owners, device/source owners, actual sources, downstream systems,
approved manual/read-only method and window, exclusions, price, timing,
handling and recipients. Both authorized parties accept the same scope version
before evidence transfer or substantive work. The customer confirms authority
for every named source, including third-party service records. If authority
is unclear, stop the affected inspection.

Ask only for named, minimally redacted evidence. Agree an existing
customer-approved transfer channel before intake; prefer a live view when it
suffices. Do not request passwords, private keys, tokens or unrelated data.
Name the operator, storage location, source-copy permission and handling
contact in the scope. Keep raw working copies only while needed; delete them
as soon as practical after that need ends and record return/deletion. **Thirty
calendar days after final handover is the default maximum, not a target
retention period.** Agree any different legal/contractual hold or backup
limitation before transfer. Delivered reports and minimal commercial records
follow their own accepted obligations.

Deliver only to named recipients through the agreed channel. More recipients
or onward sharing need customer decision-owner approval. Keep raw customer
evidence out of public repos, issues, marketing and fit-check messages.

Stop affected work and record the coverage status if authority, privacy or
provenance is unclear; a source exposes secrets/unrelated sensitive data;
a required source fails or is withheld; device/action/identity/downstream
boundary changes; or an unapproved method or system change would be needed.
Tell the decision owner which question cannot be answered. Continue only via
an approved alternative source, written fee/date/scope change, or qualified
report that marks the gap. Customer-specific terms must cover cancellation,
rescheduling and refund consequences; none is assumed here.

## Limits, tools and separate pilot

Base method is **manual and read-only**. It does not execute the proposed
action, exploit, remediate, modify production, collect secrets, install a
platform, monitor continuously or certify safety, compliance or production
readiness. Active tests and broader access need separate written scope and
authority. A receipt or sample proves only its own named verifier and evidence;
none is promised as a standard deliverable. WOPS-assisted observation is not
required, and no current WOPS implementation is represented as a released
desktop Agent/MCP collector.

The **private €950 excluding VAT pilot** is a separate manually delivered
entry scope: one device, one named agent setup, one selected connection and
one proposed action; compact setup/action map, key permission/evidence gaps,
prioritized findings and readout. It excludes the full review's system-level
inventory and has no public catalogue identity. Payment is before start;
target handover is five working days after the same documented start gates,
adjusted to its scope. A later full review needs a new quote and acceptance;
no automatic credit, discount or reserved price applies. Reuse pilot evidence
only with permission and a freshness/provenance check.
